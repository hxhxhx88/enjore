# Tech stack

The codebase is built on modern open-source projects from the TypeScript ecosystem, following an opinionated set of current best practices.

## Language

The primary language is [TypeScript](https://www.typescriptlang.org/).

## Frontend

- Framework: [Next.js](https://nextjs.org/).
- Components: [shadcn](https://ui.shadcn.com/) on top of [Base UI](https://base-ui.com/) primitives.
- Styling: [Tailwind CSS](https://tailwindcss.com/), with the [cn](https://github.com/shadcn-ui/cn) helper for class merging.

## Backend

- [Next.js server actions](https://nextjs.org/docs/app/getting-started/updating-data) — the web apps call their own backend through server actions; there is no separate API server.
- Sessions — database-backed cookie sessions and email sign-in codes, implemented in `apps/app-next` (`docs/implementation/0001-web-session.md`).
- [Prisma](https://www.prisma.io/) — database ORM.
- [PostgreSQL](https://www.postgresql.org/) — relational database.

## Libraries

- [Zod](https://zod.dev/) — schema validation at both build time and runtime.
- [Zustand](https://github.com/pmndrs/zustand) — frontend state management.
- [React Query](https://tanstack.com/query/latest/docs/framework/react/overview) — server state management and data fetching.
- [TanStack Table](https://tanstack.com/table/latest) — headless tables.
- [React Hook Form](https://react-hook-form.com/) — form state and validation.
- [Lingui](https://lingui.dev/) — internationalization (i18n).
- [react-email](https://react.email/) — building email templates.

## Tooling

- [Task](https://taskfile.dev/) — defines and runs CLI tasks for common operations.
- [pnpm](https://pnpm.io/) — monorepo package management, with a version catalog and supply-chain policies in `pnpm-workspace.yaml`.
- [Turborepo](https://turborepo.dev/) — task orchestration and caching.
- [antfu/eslint-config](https://eslint-config.antfu.me/) — linting and formatting, with the typescript-eslint type-aware rules, the React hooks and compiler diagnostics, and [jsx-a11y](https://github.com/jsx-eslint/eslint-plugin-jsx-a11y) for accessibility. Warnings fail the gate.
- [Vitest](https://vitest.dev/) — unit tests.
- [knip](https://knip.dev/) — unused files, exports and dependencies.
- [Renovate](https://docs.renovatebot.com/) — dependency updates (`renovate.json`).

## Upgrade notes

Some versions are held back on purpose. Revisit them when the blocker disappears; `renovate.json` encodes the same limits.

- Next.js stays on 16.2.x: `@lingui/swc-plugin` has no build for the SWC runner shipped by Next.js 16.3 (see [lingui/swc-plugin#253](https://github.com/lingui/swc-plugin/issues/253)). Once a compatible plugin ships, upgrade both together and consider `next/root-params` for the locale and the agent docs generated by `next dev`.
- `@lingui/swc-plugin` stays on 6.6.x for the same reason.
- TypeScript stays on 6.x: typescript-eslint cannot run on TypeScript 7 until the TypeScript 7.1 programmatic API lands.
- Prisma stays on 7.9.x: 8 is still a release candidate, and the 7.10.0 CLI was published without provenance, which the pnpm trust policy rejects.
- The React Compiler is enabled for `apps/admin-next` only: Next.js cannot order it after the Lingui SWC plugin, so Lingui macros in `apps/app-next` may break under the compiler.
