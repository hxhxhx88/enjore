# Shell and awards

The first milestone of the admin in `apps/admin-next`. It removes the template's Users pages, lays down the shell and the patterns every later milestone copies, makes awards, tiers and editions manageable, seeds the awards the product launches with, and spikes the path from a Claude Code cloud routine to the admin's tool endpoint. It implements "Manage awards" of `docs/product/0001-admin-web.md` and the "Sources" and "Marks" sections of `docs/product/0000-project-overview.md`. Nothing has to exist before it beyond the schema.

## Goal

- The operator opens the admin and sees "Dashboard", "Awards" and "Settings"; the MICHELIN Guide exists with its tiers; an unknown glyph key renders the generic mark.
- Claude has called the admin's endpoint with a valid secret, first from a cloud routine and then through the claude.ai custom connector that replaced it, so milestone 0005 builds on a path that is known to work.

## Scope

- In: template cleanup, routes and sidebar, the list, detail, form and action patterns, the marks registry, awards, tiers and editions, award seeds, the "Settings" and "Dashboard" skeletons, the admin's vitest project, the endpoint spike.
- Out: restaurants (0002), accolades and the edition page's tables (0003), imports (0003 and 0005), the queue behind the endpoint (0005).

## Design

- Template cleanup: delete `src/app/(body)/users/**`, `src/app/@header/users/**`, `src/components/table-users/`, `src/components/detail-user/`, `src/components/form-user-add/`, `src/components/form-user-edit/` and `routes.users`. The `User`, `Session` and `Verification` models stay; `apps/app-next` uses them.
- Routes in `src/lib/routes.ts`: `home`, `awards.list`, `awards.detail(id)`, `awards.edition(awardId, editionId)` and `settings`. Typed routes reject a link to a page that does not exist, so the sidebar grows with the pages: "Restaurants" arrives in 0002 and "Jobs" in 0005.
- Sidebar: `src/components/app-sidebar.tsx` lists "Dashboard", "Awards" and "Settings"; the active item is computed from `usePathname` in a client `src/components/app-sidebar-item.tsx`. The layout title names the product's admin instead of "Starter Template".
- Every body route gets a page under `src/app/@header/` for its breadcrumb, because the slot's `default.tsx` calls `notFound()`.
- List page pattern, written once here and copied later (`docs/development/0003-coding/list-page.md`): `search-parameters.ts` next to the page holds the Zod schema of `searchParams` (`page` with `.catch(1)`, enum filters with `.catch(undefined)`, `q` trimmed and capped with `.catch('')`), the filter options and `pageSize` of 50; the server page runs `Promise.all([findMany, count])` and renders `src/components/table-<entity>/`, whose `select.ts` holds the Prisma `select` and the `Row` type, `columns.tsx` the `makeColumns` factory, `table.tsx` the client table over `DataTable` from `@repo/ui-web/data-table`, and `index.ts` re-exports `select` and the table. The filters and `Pagination` read the search parameters, so each sits inside `Suspense`. Filter controls are client components, `src/components/filter-select.tsx` and the debounced `src/components/filter-search.tsx`, that write their parameter with `searchWithParameters` from `useHrefWithParameters` in `src/lib/hooks.ts` and `router.replace`, resetting `page`; links that keep the other parameters use its `hrefWithParameters`, as `src/components/link-parameters.tsx` does.
- Detail page pattern (`docs/development/0003-coding/complex-component.md`): the server page loads with `findUniqueOrThrow` and the `select` from `src/components/detail-<entity>/select.ts`, which also names the row types; `context.tsx` holds the zustand store, whose `modalData` is a discriminated union `ModalData`, and the props context with `useStore` and `useProps`; `provider.tsx` creates the store and mounts `modal-controller.tsx`; `header-<entity>.tsx`, `section-*.tsx`, the `modal-*.tsx` files and the `action-*.ts` they call sit beside them, and `index.ts` exports the provider, the header, the sections and the select. Buttons set `modalData`; modals unmount in `onOpenChangeComplete`, as `docs/development/0003-coding/modal.md` describes.
- Form pattern: one folder per entity serves create and edit through `initialValues` (`schema.ts`, `provider.tsx`, `hooks.ts`, `form.tsx` marked `'use client'`, `field-*.tsx`, `index.ts`, and `data.ts` with the tested `toData` and `toFormValues` mappers when form values and columns differ, such as `''` for `null`), as `docs/development/0003-coding/form.md` describes; `index.ts` also exports `formSchema<Entity>` and the mappers for the actions, and shared rules live in `src/lib/form-schemas.ts` and `src/lib/text.ts`. The template's duplicated add and edit folders are not copied.
- Action pattern: `action-<entity>-<verb>.ts` next to the component that calls it (`src/actions/` only for an action two pages share, such as `action-edition-update.ts`), exporting `action<Entity><Verb>`, marked `'use server'`, parsing its input again with the form's Zod schema and returning `ActionOutput` from `src/lib/action-output.ts` (`{ type: 'ok' }`, or `{ type: 'bad', message }` with `invalidInput` for a failed parse; `actionAwardCreate` adds the new `id` so the client can open it), revalidating inside, leaving navigation to the client. Only the results of `parseDatabaseError` are caught; everything else throws.
- `parseDatabaseError` moves from `src/lib/db.ts` to a pure `src/lib/db-error.ts`, because its tests cannot import `db.ts` (which validates the environment at import, and CI has none), and is widened from `User.email` to every unique key user input can violate (`slug` of restaurants, chains and awards, `restaurants.google_place_ref`, `award_tiers (award_id, name)`, `award_editions (award_id, label)`, `source_references (award_id, listing_url)`, `accolades (restaurant_id, edition_id, tier_id)`, `translations (locale, table, record_id, field)`, `poster_artworks.url`, and `restaurant_id` of profiles and drafts, told apart by model) and to the `Restrict` foreign keys a delete can hit. It returns `{ kind, message }` with a written message per known key and falls back to naming the model and the columns.
- Marks registry: `packages/ui-web/src/lib/glyphs.ts` lists `knownGlyphKeys` (`star`, `diamond`, `toque`, `fork`, `radish`, `pin`, `leaf`, `generic`) with `isGlyphKey`, and `packages/ui-web/src/mark.tsx` maps each to a drawing (lucide icons for now, typed so hand-drawn SVG components drop in later), with `Mark({ glyphKey, count })` repeating it `count` times, clamped to 1 to 10, and falling back to `generic` for a key it does not know. `packages/ui-web/src/mark-accolade.tsx` renders a tier mark, `#7`, `97.5/100`, a label, or the generic mark for a plain membership, from plain props, so the public web reuses it later. Imported as `@repo/ui-web/mark` and `@repo/ui-web/mark-accolade`.
- Derived state: `src/lib/derive-import-status.ts` returns verified, imported, importing or not imported from `verifiedAt`, `importedAt` and whether an unfinished import job targets the edition, which no caller passes before 0005.
- Slugs: `src/lib/slug.ts` exports `slugify` and `firstLatinName`; the award form fills a new award's slug from its name with `slugify` until the operator types one, and a name with no Latin letters leaves it empty and required. `firstLatinName`, which picks the first Latin-script name among a canonical name and its translations, waits for the restaurant form of 0002. Unit tests cover accents, punctuation and CJK input.
- "Settings" at `/settings`: a table of integrations and runner secrets with their variable names and "Configured" or "Not configured", built by `readSettings` in `src/lib/settings.ts` from the presence of the variables in `src/lib/env.ts`. This milestone lists "Database", "Basic Auth" and "Claude connector secret"; later milestones append their rows there. Values are never shown.
- "Dashboard" at `/`: the cards whose data exists at this point, editions awaiting verification and the awards; restaurant counts arrive in 0002, jobs in 0005, missing fields and activity in 0006.
- Seeds: `apps/cli-bun/src/actions/seed-awards/` with `awards.ts` describing the ten sources marked "Seeded" in the overview's table (name, locale, slug, short name, website, facets, score scale, tiers with level, glyph key and count) and `index.ts` upserting, one transaction per award, awards by slug, tiers by award and name, and the translations of award and tier names by their unique key; a re-run leaves `isActive` and operator-added tiers alone. A tier may use a glyph key the registry does not draw yet and renders the generic mark until a drawing is added. `apps/cli-bun` gains `@repo/db`, `@repo/lib` and a `src/lib/env.ts` on `@t3-oss/env-core`; the command runs with `task cli -- seed-awards` against the database in `.env.local`.
- Tests: `apps/admin-next/vitest.config.ts` mirrors `apps/app-next/vitest.config.ts` and is registered in the root `vitest.config.ts`.
- Endpoint spike: `src/app/api/mcp/route.ts` is the admin's only route handler, `POST` only with `maxDuration` of 60, serving the MCP TypeScript SDK's stateless Streamable HTTP transport (`createMcpHandler` from `@modelcontextprotocol/server` in `src/lib/mcp/server.ts`, one server per request with `responseMode: 'json'` and `maxSubscriptions: 0`). `src/lib/mcp/auth.ts` maps `Authorization: Bearer` to a runner by constant-time comparison; `secureEquals` moves from `src/proxy.ts` to `src/lib/crypto.ts` so both use it. The spike registers `claim-job` alone and returns no job because the queue is empty, which is a valid answer under `packages/lib/src/schemas/job-tool.ts`. For the spike, `.mcp.json` at the repo root declared the `admin` server at `${ADMIN_MCP_URL}` with the header `Authorization: Bearer ${RUNNER_SECRET_CLOUD_TASK}`, both set in the routine's environment. The proxy's matcher already skips `/api`, so the route protects itself. The exception to the server-action rule is recorded in `docs/development/0003-coding/nextjs-server-action.md`. Outcome: the routine's run of 2026-10-21 proved the path; the same day the connection moved to a claude.ai custom connector carrying the secret as a request header, `.mcp.json` was removed and the runner became `claude` with `RUNNER_SECRET_CLAUDE`, as the index records.
- Primitives installed with `task ui:web -- <name>`: select, textarea, checkbox, switch, badge, card. Tabs wait for the first milestone that needs them (0004).

## Work

- Remove the Users pages, components and route entries; rename the layout title; run `task check` to confirm the template compiles without them.
- Add the routes, the sidebar with the active item, and the `@header` pages for "Awards", the award detail, the edition detail and "Settings".
- Install the primitives; add the admin vitest project.
- Write `slug.ts`, `derive-import-status.ts` and the widened `parseDatabaseError`, with tests.
- Add `mark.tsx` and `mark-accolade.tsx` to `packages/ui-web`.
- Build `form-award`, `form-award-tier` and `form-award-edition` with their actions.
- Build "Awards" at `/awards`: name, short name, slug, facet badges (tier, rank, score, label), active, tier and edition counts; "Add award" opens a sheet with the form.
- Build `/awards/[id]` with `detail-award`: the fields with "Edit"; the tiers table with a live `Mark` preview and add, edit and delete modals; the editions table with import status and add and edit modals; "Deactivate" and "Activate"; "Delete", refused while accolades or source references point at the award: the modal says so instead of offering the button, and the action counts both and maps a racing `Restrict` violation to the same bad message.
- Build `/awards/[id]/editions/[edition-id]` with the edition's fields and "Edit"; counts, tables and import actions are added by 0003 and 0005.
- Build "Settings" and the "Dashboard" cards.
- Write the seed data and command; run it against the development database, then production.
- Spike: the route, the auth module, `.mcp.json`, the environment variable and the Settings row; deploy; a routine whose prompt listed the tools called `claim-job`, and the run log showed the authenticated call. The claude.ai custom connector then replaced `.mcp.json`, which was deleted; `.gitignore` and `.claude/settings.json` stayed as they were.
- Record the route-handler exception in `docs/development/0003-coding/nextjs-server-action.md`.

## Done when

- The Users pages are gone and `task build` passes.
- Awards and tiers are created, edited and deleted, and editions created and edited, in production; a tier's mark previews live.
- The seeds are applied: the MICHELIN Guide has its tiers and the operator adds the "Hong Kong Macau 2026" edition.
- The routine's run log shows one authenticated `claim-job` call that returned no job (seen on 2026-10-21; the connector repeats the call from a chat, a chat task, a cloud task without repository and the terminal).
- Acceptance scenario: adding "We're Smart World" with an unknown glyph key renders the generic mark, with no code change.

## Boundaries

- Chains, restaurants and accolades are not edited; the award detail shows tier, edition and accolade counts, and its delete check also counts source references.
- The endpoint has no queue behind it; 0005 replaces the stub `claim-job` with the real one.
